# GitLab workbench

Этот репозиторий — рабочее место для задач по проектам в **GitLab**. Своего кода тут нет: проекты клонируются из GitLab в `~/gitlab/`, исправления уходят туда же через merge request.

Инструмент — `bin/gl` (git + GitLab API, токен берётся из `GITLAB_TOKEN`, хост — из `GITLAB_HOST`, по умолчанию gitlab.com).

## Как работать

1. Склонировать проект: `bin/gl clone group/project` → путь в `~/gitlab/project`.
2. Перейти туда, разобраться в коде, при необходимости запустить тесты.
3. Для исправления — новая ветка: `git checkout -b fix/<коротко-о-сути>`, коммиты с понятными сообщениями.
4. Открыть MR из каталога проекта: `<путь-к-этому-репо>/bin/gl mr "Заголовок" "Описание: что было, что сделано, как проверить"`.
5. Вернуть пользователю ссылку на MR.

Полезное через API (id проекта — путь с `/` → `%2F`):
- пайплайны: `bin/gl api "projects/group%2Fproject/pipelines?per_page=5"`
- лог джобы: `bin/gl api "projects/group%2Fproject/jobs/<job_id>/trace"`
- issues: `bin/gl api "projects/group%2Fproject/issues?state=opened"`
- MR: `bin/gl api "projects/group%2Fproject/merge_requests?state=opened"`

Если пользователь просит только разобраться («почему падает», «где это считается») — исследуй и отвечай, ветки и MR не создавай.

## Правила

- **Никогда** не выводи, не логируй и не коммить значение `GITLAB_TOKEN`; не вставляй его в URL remote.
- Не пушь в ветку по умолчанию и не мёржь MR — только новая ветка + MR, мёржит человек.
- Не делай force push в чужие ветки.
- Изменения в этот репозиторий (workbench) не коммить, если об этом прямо не попросили.
